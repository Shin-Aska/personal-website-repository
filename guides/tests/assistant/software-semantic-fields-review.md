# Whole-source software semantic fields

This reader extends the existing capability helper with `software-field`
descriptors and `readSoftwareSemanticFields(fact, {subjectLabels})`. The
exported reader returns field names, never a rewritten answer. The caller
continues to select eligible sources, resolve canonical owners, enforce edition,
spoiler, material, numeric, state and compound-question restrictions, and render
the complete accepted original witness.

The source basis is the complete existing StarCraft knowledge manifest,
`guides/StarcraftBWAPI.html`, and the complete failed rows, rendered replies,
citations and same-dialogue transcripts in
`knowledge-full-corpus-review-starcraft-albion-20261025-02.json`. External
research remains bounded to the reviewed local records checked 2026-10-24.
Nothing was downloaded, installed, trained or fetched from upstream.

The relevant distinctions are source fields rather than lexical relevance:

| Field | Complete proof and retained qualification |
| --- | --- |
| Purpose | Standard-AI replacement in single-player mode, or the complete programming-API/opponent distinction; invocation is insufficient. |
| Defaults and changed defaults | Normal hidden-state and human-control restrictions, tournament enforcement, announced changes and the no-universal-guarantee qualification remain together. |
| Packaged opponent | Complete C++ framework description and explicit programming API/prepackaged-client distinction. |
| Game installation and compatibility | Separate Brood War 1.16.1 installation, conflicting Remastered prerequisites and the cannot-confirm conclusion remain together. |
| Internet/network | SCHNAIL's initial-login and subsequent local-network scopes remain distinct from BWAILauncher's complete offline profile. |
| Java runtime | The full SCHNAIL Java recommendation or PurpleWave's 32-bit JDK 8, 32-bit BWAPI and explicit SCHNAIL contrast remain intact. |
| Map method, map scope and map mode | Direct Remastered/no-launcher capability, provided integrated maps, Use Map Settings and the standard-Melee restriction require their complete respective witnesses. |
| Developer target | The reviewed README quick start's 1.16.1 target and non-certification of arbitrary Remastered binaries remain together. |
| Binary configuration | Matching-version JSON in bwapi-data/AI, BWAPI 4.4.0 and the distinction from the Remastered map archive remain together. |
| Component function | The complete SparCraft combat-simulator and BOSS build-order/search relationship; compiler-version text does not prove the requested function. |
| Community category | A complete subreddit label with its matching Reddit resource link; GitHub Discussions cannot satisfy the category. |

The parser preserves complete captured subject, target, source and artifact
complements. Its `contextFieldText` marks an inherited property, never a player
action. Defaults, replacement mode and component follow-ups require a matching
complete source fact actually returned by the caller. Full related-source
quotes can supply evidence even when the previous reply declined an unrecorded
deeper explanation. User text, aliases or a failed answer alone cannot.

An omitted Java comparator and an explicit-target `instead` require separately
resolved `referenceEntityId` and `referenceLabels`, plus a complete Java witness
actually returned for that owner. The current PurpleWave witness must explicitly
name the comparator in its do-not-substitute clause. The SCHNAIL `instead`
request additionally restricts the answer to an extracted guide witness. An
internet comparison uses the same independently resolved prior-owner contract.

Elliptical tool ownership requires an established canonical focus and a full
returned source proof. Complete recorded identity/download witnesses can
establish the owner for a later runtime or JSON-destination request without
establishing the new requested property. A partial sentence, a changed witness,
an unrelated owner or an absent source cannot establish that continuity.

The existing general conflict rejection is retained. The one bounded exception
requires `software-field`, the full original installation-conflict wording,
matching canonical subject labels, every required relation and
`source.review === 'conflicting'`. Its answer is the qualified conflict itself;
it cannot certify compatibility or authorize a different conflicting fact.

Focused tests pair each positive with missing qualifications, clipped or
extended witnesses, wrong owners/fields, absent relations/source/locator,
modified descriptors, missing returned evidence, unrelated prior properties,
wrong comparators, guide/research substitution and unknown source, edition,
material, numeric and compound modifiers. The tests read actual existing facts;
synthetic mutations are negative probes, not changed knowledge or frozen
oracles. The original twelve capability tests and ten new semantic-field tests
pass with the bundled Node runtime. These are source-reader regression checks,
not a claim of improved model accuracy or an exhaustive corpus acceptance.

The offline-comparison regression also replays the first two exact full03
corpus turns through `createConversationAssistant`. Its offline-benefit
antecedent must return the full unconditional profile before the SCHNAIL
network contrast can inherit it; a failed antecedent never licenses comparison.
