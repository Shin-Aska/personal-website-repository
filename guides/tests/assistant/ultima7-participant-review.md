# Ultima VII participant metadata review

This review changes metadata only in `guides/data/assistant/knowledge/ultima7.json`. The 123 fact IDs, subjects, facets, aliases, text, witnesses, sources, source record IDs, research witnesses and edition fields are unchanged. Every `knowledgeDocument` remains identical to the existing embedding catalog. There are no new facts, encoded documents, question-shaped aliases, production models, downloads or frozen-oracle edits.

The original Courage source, `DB.virtueQuests[5]`, describes mages, golems and dragons, then instructs the reader to defeat Dracothraxus for the Ether Gem. The shorter `ether-gem-dragon` witness omits the creature noun. The existing precise `defeat-to-obtain` edge still runs from Dracothraxus to the Ether Gem; it now includes the complete `courage-sleep-potions` proof and the existing Courage editorial source context. The quest, obtainable item and animate opponent retain separate IDs. No voluntary gift, inventory state, or new creature subtype is asserted. The marker for Dracothraxus calls it a creature and says only “Friendly and aggressive”; it is not a standalone dragon-type proof.

The complete original forging source, `DB.virtueQuests[6]`, names Arcadion, the Ether Gem, the mirror, the daemon and the Black Sword in one procedure. Its existing `binds-daemon` edge is retained, requiring that complete procedure as its full proof. The separate Arcadion daemon-identity fact remains unchanged as corroboration. New direct `binding-vessel` and `binding-instrument` edges run from the Black Sword to the Ether Gem and mirror respectively; `freed-via` runs from Arcadion to the mirror. Each new edge is witnessed by the complete original forging instruction and carries its source context. These edges index source participants; they do not traverse the Arcadion-to-gem edge to invent a sword-to-gem prerequisite. The existing Arcadion-to-Ether-Gem `freed-into-via-mirror` edge remains intact. Literal mirror method bindings do not claim how to acquire or locate the mirror. Arcadion's marker witness explicitly says “The bound daemon of the Blackrock Sword”.

The original Magebane equipment entry states `Drains Mana on Hit`. Its existing `drains-on-hit` edge remains exact; the literal effect is now also a descriptive topic label. The source supports quoting the stated trigger. It does not independently establish an exclusive “only” rule or a negative passive-carrying rule.

## Shared reader integration

Before this review, `knowledge-graph.js` already read the incoming `defeat-to-obtain` predicate as a provider direction and kept edge direction independent of query subject order. It required every evidence fact to pass the caller's eligibility checks and returned full existing witnesses. Its question parser did not recognize `which dragon has ...`; the `which person` branch also excluded creature nouns. Its predicate table did not read `binds-daemon`, `binding-vessel`, `binding-instrument`, `freed-via` or `freed-into-via-mirror`. The finite factual-property reader did not parse an on-hit versus carrying contrast. Metadata alone therefore does not establish that the three observed conversations now pass.

The shared graph reader now recognizes a bounded animate-holder WH request, anchors the requested item separately from the editorial quest scope, and reads only the direct authored holder predicate. A requested creature noun must occur in the same literal source sentence as the answer's name, without a negated or uncertain type assertion. No subtype metadata is invented. Dracothraxus remains the returned participant, the Ether Gem remains the held/obtainable item, and the Courage context remains scope. A source restriction, unknown item or unrelated test fails closed. The full scene label must match a declared editorial context; the exact grammatical inversion `Test of Courage` / `Courage test` is supported without adding synonyms.

The reader now reads the active artifact's direct `binds-daemon` and `binding-vessel` edges as separate participant slots. A requested daemon noun needs literal named proof. The gem question uses the direct vessel edge or, with an independently grounded Arcadion focus, the exact `freed-into-via-mirror` edge. The named actor-to-vessel clause must remain literal in the evidence; mirror remains an instrument, never the destination vessel. The caller must render the complete source facts, preserve Forge of Virtue eligibility and the established artifact focus, and resolve compound clauses atomically. No daemon or gem name appears in generic runtime code.

The artifact's complete source can also establish the binding actor's type through a bounded same-fact action antecedent. A reviewed direct artifact-to-actor binding edge must have one artifact-owned method witness whose text equals its full witness. That witness must contain exactly one imperative `Free <unique named actor> into <vessel> via <instrument>` before the later literal `bind the <requested type> to forge <exact named artifact>` action. Negation, uncertainty, another or multiple freed actors, another artifact, reversed action order or a truncated witness fails this proof. An unrelated co-mentioned person in an ask-about action is not the freed actor. An artifact-owned paragraph cannot use ordinary noun co-occurrence to bypass this check.

This keeps the complete Forge of Virtue procedure eligible under the inherited edition filter without importing the untagged marker identity into that edition. The marker is no longer a required proof for the procedural edge; its fact, source and empty edition metadata remain unchanged. Every required procedure fact still passes the same eligibility callback, so an unknown edition remains unsupported. There is no global edition-guard exception.

The graph lookup now accepts optional `sourceContexts` and `referenceEntityIds`. Typed holder descriptors preserve `requestedKind`, `subjectLabel` and `sceneLabel`. Binding-vessel descriptors preserve `requestedParticipantLabel`; pronouns with an artifact focus require one valid canonical referent passed in `referenceEntityIds`, while one animate active subject can ground its own object pronoun. The caller must keep the artifact focus and the returned actor reference separate and include the new finite role names in its unsupported-role boundary. Missing, multiple or unknown referents fail closed.

The same shared reader accepts a bounded entry-dependency assertion such as `Do I really need him to get inside ...?`. Its descriptor preserves the exact named destination as `subjectLabel`, the dependency as `requestedDependencyLabel`, and `assertion: true`. A positive result requires a correctly directed direct requirement for that specific resolved dependency and a literal entry-gate clause naming it. Another prerequisite, a co-mentioned actor, a route instruction or historical recruitment cannot satisfy the assertion. The caller must pass the canonical named destination and the resolved dependency, and retain its normal source/edition/compound eligibility checks.

For the combat-property follow-up, a generic trigger reader can match the exact literal `drains-on-hit` relation and `Drains Mana on Hit` equipment witness for a grounded subject. Returning that witness supports the positive source statement without synthesizing an unwitnessed passive-carrying exception. Unknown triggers, resources, materials, editions, save-state predicates and mixed compound restrictions must remain constraints.

This is a static contract result, not a frozen-corpus or native browser acceptance result.

New paired checks cover actual Forge of Virtue eligibility with no marker proof visit, unknown-edition rejection, another/multiple actor, multiple freeing actions, wrong artifact, reversed order/direction, negated or uncertain actions, unknown type, truncated action/witness and a co-mentioned actor outside the freeing slot.
